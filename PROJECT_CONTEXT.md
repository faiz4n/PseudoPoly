# PseudoPoly — Master Project Context & Technical Handover Guide

> **Purpose**: This document provides complete architectural, functional, and operational context for PseudoPoly. If a new AI agent, engineer, or team member takes over this repository, this file contains all background, system design decisions, past bug investigations, recent fixes, and instructions needed to continue development immediately.

## 1. Project Overview & Architecture

**PseudoPoly** is a modern, fast-paced, high-stakes real estate trading board game (Monopoly-style) built for Web and Android.

### Tech Stack
- **Frontend**: React 19 + Vite (Single Page App). Uses standard HTML5, CSS3, and HTML5 Web Animations / Canvas.
- **Mobile Container**: Capacitor 7 (`@capacitor/android`, `@capacitor/core`) wrapping the Vite web build in an Android `WebView`.
- **Backend (Online Multiplayer)**: Node.js + Express + Socket.IO server hosted on Render at `https://pseudopoly.onrender.com` (source in `server/index.js`).
- **Backend (Offline Hotspot Multiplayer)**: Embedded Java WebSocket server inside the Android APK (`HotspotGameServer.java`) combined with a UDP beacon discovery protocol (`MainActivity.java`).

## 2. The Two Multiplayer Systems (CRITICAL DISTINCTION)

PseudoPoly features **two completely separate multiplayer pipelines**. Never confuse or mix them up:

### System A: Online Multiplayer (Internet / Web & Mobile)
1. **Server**: Hosted Node.js/Socket.IO backend at `https://pseudopoly.onrender.com`.
2. **Client**: Connects via `socket.io-client` (`socketRef.current = io(serverUrl, ...)`).
3. **Room Codes**: 4-digit numeric room codes generated by the server.
4. **Authoritative State**: The server runs `handleLanding`, `handleRollDice`, `handleBuyProperty`, `handleAttemptRobbery`, and broadcasts updates to room sockets via `state_update`.

### System B: Hotspot / LAN Multiplayer (Offline / Direct Wi-Fi)
1. **Concept**: "Mini-Militia style" local play without internet. One device hosts a Wi-Fi hotspot; others connect to it.
2. **Embedded Server**: `HotspotGameServer.java` runs an embedded Java WebSocket server on port `8080` (or dynamic fallback) on the host's Android device.
3. **Discovery**:
   - Host broadcasts UDP beacons containing `{ roomCode, hostName, ip, port }` over port `8888`.
   - Android Multicast lock (`WifiManager.MulticastLock`) is acquired in `MainActivity.java` with permission `CHANGE_WIFI_MULTICAST_STATE`.
   - Clients scan UDP on port `8888` via `lanDiscovery.startScan` (or fallback subnet probing) to discover local games without requiring any manual IP entry or codes.
4. **Host IP Resolution**: Dynamically resolved from active network interfaces (`wlan`, `ap`, `rndis`, `swlan`); there are no hardcoded laptop IPs.

## 3. Game Mechanics & Board Systems

### Board Geometry & Coordinates
- **Tile Count**: 40 tiles total (4 corners + 4 sides of 9 tiles each).
  - Tile 0: **START (GO)** — Bottom-Right
  - Tiles 1–9: Bottom row (Right to Left)
  - Tile 10: **PARKING (Cash Stack / Free Parking)** — Bottom-Left
  - Tiles 11–17: Left column (Bottom to Top)
  - Tile 18: **ROB BANK** — Top-Left
  - Tiles 19–27: Top row (Left to Right)
  - Tile 28: **JAIL (Go To Jail / Arrest)** — Top-Right
  - Tiles 29–35: Right column (Top to Bottom)
- **Coordinate Math**:
  - `getTileCenter(tileIndex)` in `src/App.jsx` calculates the exact `(x, y)` center of every tile in `vh` units relative to the 100vh board.
  - `getPawnStyle(tileIndex, playerIndex)` places player pawns with neat 2x2 offsets when multiple players share a tile, and centers moving pawns during hop animations.

### Special Tiles & Mini-Games
1. **Rob Bank (Tile 18)**:
   - Suspenseful 5-second mini-game with an animated sliding needle across 3 possible outcomes:
     - **Busted / Jail (1/3 probability)**: Sent to Jail (tile 28) for 3 turns.
     - **Escaped (1/3 probability)**: Escaped guards empty-handed ($0).
     - **Rob Bank Jackpot (1/3 probability)**: Stole between $1,000 and $10,000 from the vault.
   - Dedicated SVG vector graphics for all outcomes (`BustedJailIcon`, `EscapedThiefIcon`, `VaultDiamondIcon`).
2. **Jail (Tile 28)**:
   - Jailed players cannot roll normally until they serve 2–3 turns or pay bail ($1,000 / $500 / $200 depending on remaining turns).
   - Jailed owners do not collect rent when rivals land on their properties.
3. **The Audit (Tile 7)**:
   - Tax collector mini-game based on the dice values that landed on the tile: `(die1 + die2) * $300`.
4. **Cash Stack (Tile 10 / Parking)**:
   - Accumulates taxes and bail fines into a center jackpot pot. Landing on it awards the entire pot.
5. **Forced Auction (Tile 31)** & **Property War**:
   - Advanced trading and hostile takeover mechanics.

## 4. Key Bugs Investigated and Resolved

### A. Avatar and Nickname Persistence
- **Problem**: Changing player name or avatar in MatchmakingView reset to static defaults on reload or restart.
- **Fix**: Initialized `myIdentity` in `src/App.jsx` from `localStorage.getItem("pseudopoly_identity")` with reactive synchronization via `useEffect`.

### B. Jail Game Freeze Bug
- **Problem**: When a player landed on Jail or clicked "I UNDERSTAND", the game permanently froze on the next player's turn.
- **Root Cause**: Dice roll set `isProcessingTurn = true`. `handleTileArrival` popped `showArrestModal` and returned. When user tapped "I UNDERSTAND", `handleEndTurn()` changed `currentPlayer` to `nextIdx`, but **never reset `isProcessingTurn(false)`**! Roll buttons were disabled whenever `isProcessingTurn` was true, locking out all future rolls.
- **Fix**: Added `setIsProcessingTurn(false)` and `setTurnFinished(false)` across `handleEndTurn`, `handleJailPay`, `handleJailSkip`, and modal buttons. Added `showArrestModal` and `showJailActionModal` cleanup to `closeAllModals` and `resetAllModals`.

### C. Rob Bank "Does Nothing / Stuck" Bug
- **Problem**: In online multiplayer, landing on Rob Bank closed the modal immediately or locked the game.
- **Root Cause**:
  1. `server/index.js` `handleLanding` **completely omitted tile 18**. 500ms after rolling, the server broadcast `state_update` with default `modalState = { type: 'NONE' }`, which triggered client line 1373 to immediately force `showRobBankModal(false)`.
  2. The "LEAVE" button called `handleCancelBuy`, designed only for property purchases, which failed to end turns or notify the server.
  3. Finishing robbery sent `close_modal` but omitted `end_turn`.
- **Fix**:
  1. Added tile 18 to `server/index.js` `handleLanding` (`modalState = { type: 'ROB_BANK', status: 'IDLE' }`).
  2. Added `handleRobBankLeave` to cleanly send `close_modal` + `end_turn` and rotate turns.
  3. Updated `handleRobBankComplete` to cleanly end the turn in online and offline modes.

### D. Tile Labels Font Size
- **Formula**: `clamp(1px, 2vh, 7.5px) !important` applied across `.tile .tile-name`, `.tile.vertical .tile-name`, and `.is-capacitor` rules to ensure crystal-clear text that never clips or overflows.

### E. Bezel / Tempered Glass Top & Bottom Margins (45px)
- **Problem**: Curved screen corners or tempered glass bezels cut off ~20-45px of the top row (Rob Bank/Jail) and bottom row (Start/Parking).
- **Fix**:
  1. Added `padding: 45px 15px;` to `.game-container`.
  2. Created `.board-wrapper` with `width: calc(100vh - 90px); height: calc(100vh - 90px);`.
  3. Scaled `.board` using `transform: scale(calc((100vh - 90px) / 100vh)); transform-origin: center center;`.
  4. Constrained `.sidebar` to `max-height: calc(100vh - 90px); height: 100%;`.
  5. This creates an exact 45px clear margin at top and bottom while keeping 100% of internal board coordinates and pawn mathematics mathematically intact.

### F. Android Notch / Cutout Shift Bug
- **Problem**: In the APK, the app didn't use notch space and was shifted to the right, causing background offset and asymmetrical layout.
- **Root Cause**: Default Android `layoutInDisplayCutoutMode` creates a black letterbox on the notch side in landscape. Asymmetrical CSS `env(safe-area-inset-left)` further shifted flex containers rightwards.
- **Fix**:
  1. In `MainActivity.java` `hideSystemUI()`, explicitly set `lp.layoutInDisplayCutoutMode = WindowManager.LayoutParams.LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES;`.
  2. In `styles.xml`, set `android:windowLayoutInDisplayCutoutMode = shortEdges`.
  3. Made container paddings symmetrical so content is centered on the physical screen.

### G. Visual Polish
- **Joining Code Display**: Enlarged the room code chip (`font-size: 22px`, bold code `28px`) and PIN input boxes (`58px x 66px`, font size `32px`).
- **Circle Avatars**: Changed `.mm-profile-avatar-frame`, `.mm-profile-avatar-img`, `.mm-avatar-thumb`, and `.mm-avatar-thumb img` from squircles to pure circles (`border-radius: 50%`).
